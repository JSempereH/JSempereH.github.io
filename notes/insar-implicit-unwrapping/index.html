The previous post built the machinery for how the unobserved state, position and instantaneous velocity, evolves between epochs, but sidestepped how it actually connects to the observed data: a wrapped, modulo-$2\pi$ phase. This post closes that gap, and in doing so runs into unwrapping again, this time solved in a completely different way than either of the previous two treatments in this series.

Three ways to handle the same problem, so far

It’s worth naming all three side by side, since this series keeps returning to the same underlying issue.

  • Post I treated unwrapping as a purely combinatorial problem: deciding how many whole $2\pi$ cycles to add back at each pixel of a single interferogram, with no time dimension involved at all.
  • Post IV treated it as one hypothesis among many: fix a candidate jump to $\pm\lambda/2$, run it through the same DIA machinery as a thermal or seasonal term, and accept the correction only if the test statistic clears its (power-calibrated) critical value.
  • This post treats it as an assumption built directly into the recursive update, with no separate test at all.

The predicted residual

Inside the recursive filter, by the time a new observation $\varphi_t$ arrives, we already have a prediction of what it should be, $A_t\hat x_{t|t-1}$, computed from the state before this epoch. Define the predicted residual as the difference between the (unknown, absolute) true phase and that prediction:

$$ \Delta\phi_t = \phi_t - A_t\hat x_{t|t-1}. $$

If the state truly evolves as smoothly as the previous post’s $(\sigma_v, \tau)$ assume, this residual should be small, a good prediction leaves little unexplained. The trouble is that we never observe $\phi_t$ directly, only its wrapped version $\varphi_t = \mathcal{W}\{\phi_t\}$. The minimum gradient assumption is the claim that

$$ |\Delta\phi_t| < \pi, $$

i.e. that the prediction is good enough that the true residual never exceeds half a wave cycle. Under that assumption, wrapping the observed mismatch recovers the true one exactly, because wrapping only changes a number when it lies outside $(-\pi,\pi]$ to begin with:

$$ \Delta\phi_t = \mathcal{W}\{\varphi_t - A_t\hat x_{t|t-1}\}. $$

This closes the loop: the absolute phase is recoverable as $\phi_t = A_t\hat x_{t|t-1} + \Delta\phi_t$, with no combinatorial search and no separate hypothesis test, unwrapping happens as a byproduct of already having a prediction, which is why this is called implicit unwrapping.

When the assumption holds, and when it doesn’t

The assumption is doing real work, and it can fail. If the true, unmodeled change since the last epoch is smaller than half a wavelength, wrapping the residual costs nothing:

import numpy as np

wavelength = 55.5  # mm, C-band

def wrap_to_phase(distance_mm, wl=wavelength):
    return np.angle(np.exp(1j * 2 * np.pi * distance_mm / wl))

def recover_mm(wrapped_phase, wl=wavelength):
    return wrapped_phase * wl / (2 * np.pi)

true_gap = 8.0  # mm, well under wavelength/2 = 27.75 mm
recovered = recover_mm(wrap_to_phase(true_gap))
print(f"true gap: {true_gap} mm, recovered: {recovered:.3f} mm")

true gap: 8.0 mm, recovered: 8.000 mm

But if the real change exceeds $\lambda/2$, wrapping silently throws away a whole cycle, and the assumption fails without any warning:

true_gap = 45.0  # mm, larger than wavelength/2 = 27.75 mm
recovered = recover_mm(wrap_to_phase(true_gap))
print(f"true gap: {true_gap} mm, recovered: {recovered:.3f} mm")
print(f"error: {recovered - true_gap:.3f} mm")

true gap: 45.0 mm, recovered: -10.500 mm
error: -55.500 mm

The error is exactly one full wavelength, $55.5\,\text{mm}$, the signature of a missed cycle. There is no statistic here that flags this the way the DIA test in post IV would; the filter just absorbs the wrong absolute value and moves on, biased by a full cycle until, if ever, later observations happen to pull it back.

Why the smoothness constraint is also the unwrapping constraint

This is the connection back to the previous post’s $(\sigma_v, \tau)$: they are not just a prior on how fast the object is believed to move, they are simultaneously the thing that determines how good the prediction $A_t\hat x_{t|t-1}$ is, and therefore how likely the minimum gradient assumption is to hold at every epoch. Tighter smoothness constraints (small $\sigma_v$, large $\tau$) produce more conservative, more confident predictions, which makes the assumption safer, but at the cost of the filter being slower to recognize a real, large, sudden displacement for what it is rather than as a cycle slip. Looser constraints make the filter more willing to follow a real large jump, but also more exposed to genuinely misinterpreting noise as motion. This is the same trade-off from the previous post, just now with an unwrapping-safety dimension added on top of the accuracy one.

The paper is explicit that this is a real, currently open weakness of the method, not a solved problem: discontinuities and outliers larger than the assumption’s reach are only detectable informally, by inspecting the predicted residuals after the fact, and explicit statistical handling of these cases (in the spirit of the DIA framework from the first arc) is flagged as future work rather than something already built in.

What is left out here

The batch initialization step (the first set of epochs, before the recursive filter takes over) does not use this implicit mechanism: it resolves integer ambiguities explicitly, via integer least squares and the LAMBDA method, an optimization over a discrete lattice of candidate integer values rather than an assumption baked into a single update equation.
