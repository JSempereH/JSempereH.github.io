This post opens a second arc within the Probabilistic InSAR series. The previous post closed the first arc, built around Chang & Hanssen (2016): a null model, a library of alternatives, and a way to pick the best-supported one via hypothesis testing. That whole pipeline assumes a batch of data: you already have all $m$ epochs, and you fit one, time-invariant set of parameters to explain the entire period at once. This post starts asking what changes when new SAR acquisitions keep arriving and you want an answer now, not after reprocessing everything from scratch. This arc follows Wang, Brouwer, van Leijen & Hanssen (2026).

What breaks about batch estimation for monitoring

Every model in the first arc, $\mathbb{E}[y] = Ax$, treats $x$ as a single, time-invariant vector that describes the entire observation period. That’s a perfectly reasonable assumption if your goal is to look back at a finished dataset and characterize what happened. It’s a much worse fit for monitoring, for two separate reasons.

The first is purely computational: every time a new acquisition arrives, $y$ grows by one entry, and recomputing $\hat x = (A^TQ_{yy}^{-1}A)^{-1}A^TQ_{yy}^{-1}y$ from scratch means redoing an $\mathcal{O}(m)$-sized linear solve, over again, for every one of possibly millions of points, every few days. Reprocessing an ever-growing history from zero doesn’t scale.

The secnd is: even if you could afford to refit instantly, a time-invariant $x$ cannot represent a scatterer whose actual behavior changes partway through the series, a building that was stable and starts subsiding once construction begins nearby, say. Refitting the same static model more often doesn’t fix this; the model itself is the wrong shape for the job. Batch refitting with a growing window, run incrementally, does track the average trend eventually, but it does so with a lag: since every past observation still pulls equally on a single time-invariant estimate, a real change in behavior gets averaged against years of “before” data and takes a long time to dominate the fit.

Both problems point the same way: we need to update an estimate one new observation at a time, without reprocessing the full history, and we need to let the estimate itself evolve rather than staying frozen. This post handles the first requirement; the next one handles the second.

Recursive least squares: updating an estimate with one new observation

Start with the easier version of the problem: $x$ really is time-invariant (nothing changes over the observation period), but we still want to fold in each new observation as it arrives, without re-solving the whole GLS system.

Suppose that after some epochs we already have an estimate $\hat x_{t-1}$ with covariance $Q_{\hat x_{t-1}}$, summarizing everything observed up to epoch $t-1$. Treat this estimate itself as a pseudo-observation: a noisy measurement of the true $x$, $\hat x_{t-1} = x + e_p$, with $e_p \sim \mathcal{N}(0, Q_{\hat x_{t-1}})$. A new real observation then arrives, $\varphi_t = A_t x + e_t$, with $e_t \sim \mathcal{N}(0, Q_{\varphi_t})$, independent of $e_p$. Stack the two:

$$ \begin{bmatrix} \hat x_{t-1} \ \varphi_t \end{bmatrix} = \begin{bmatrix} I \ A_t \end{bmatrix} x

  • \begin{bmatrix} e_p \ e_t \end{bmatrix}, \qquad \operatorname{Cov} = \begin{bmatrix} Q_{\hat x_{t-1}} & 0 \ 0 & Q_{\varphi_t} \end{bmatrix}. $$

This is exactly the GLS setup from the second post, just with a stacked design matrix and a block-diagonal covariance. Plugging it into the usual GLS formula $\hat x = (\mathbf{A}^T Q^{-1} \mathbf{A})^{-1}\mathbf{A}^T Q^{-1}\mathbf{y}$ and expanding the blocks gives

$$ \hat x_t = \left(Q_{\hat x_{t-1}}^{-1} + A_t^T Q_{\varphi_t}^{-1} A_t\right)^{-1} \left(Q_{\hat x_{t-1}}^{-1} \hat x_{t-1} + A_t^T Q_{\varphi_t}^{-1} \varphi_t\right), \qquad Q_{\hat x_t} = \left(Q_{\hat x_{t-1}}^{-1} + A_t^T Q_{\varphi_t}^{-1} A_t\right)^{-1}. $$

Notice what this says about precision (the inverse of covariance): the new precision is simply the old precision plus the precision contributed by the new observation, $Q_{\hat x_t}^{-1} = Q_{\hat x_{t-1}}^{-1} + A_t^T Q_{\varphi_t}^{-1} A_t$. Independent Gaussian information adds in precision, not in covariance, this is the whole mechanism, and it means updating requires only $\hat x_{t-1}$ and $Q_{\hat x_{t-1}}$, never the raw observations that produced them.

Note. The formula above can be rearranged into the more familiar measurement-update form. Multiply the definition $Q_{\hat x_t}^{-1} = Q_{\hat x_{t-1}}^{-1} + A_t^T Q_{\varphi_t}^{-1} A_t$ on the left by $Q_{\hat x_t}$:

$$ > I = Q_{\hat x_t} Q_{\hat x_{t-1}}^{-1} + Q_{\hat x_t} A_t^T Q_{\varphi_t}^{-1} A_t > \quad\Longrightarrow\quad > Q_{\hat x_t} Q_{\hat x_{t-1}}^{-1} = I - Q_{\hat x_t} A_t^T Q_{\varphi_t}^{-1} A_t. > $$

Substitute this into $\hat x_t = Q_{\hat x_t}\left(Q_{\hat x_{t-1}}^{-1} \hat > x_{t-1} + A_t^T Q_{\varphi_t}^{-1} \varphi_t\right)$, distributing the first term:

$$ \hat x_t = \left(I - Q_{\hat x_t} A_t^T Q_{\varphi_t}^{-1} A_t\right)\hat x_{t-1}

  • Q_{\hat x_t} A_t^T Q_{\varphi_t}^{-1}\varphi_t = \hat x_{t-1} + Q_{\hat x_t} A_t^T Q_{\varphi_t}^{-1} \left(\varphi_t - A_t \hat x_{t-1}\right). $$

So, the update is: predict what the new observation should be, $A_t \hat x_{t-1}$, compare it to what was actually observed, $\varphi_t$, and nudge the estimate in proportion to that mismatch, weighted by how much precision the new observation carries relative to the current estimate.

The recursion is exact

It’s worth being explicit about something easy to miss: this recursive update produces exactly the same $\hat x_t$ and $Q_{\hat x_t}$ you would get by running the full batch GLS solve on all $t$ observations at once, under the time-invariant model. Nothing is being approximated, the algebra above is just a rearrangement of the same GLS problem into an incremental form. The only thing that changes is that the cost of incorporating one new epoch no longer grows with how much history came before it.

import numpy as np

rng = np.random.default_rng(0)

m, n = 40, 2                      # 40 epochs, 2 parameters (offset, velocity)
t = np.arange(m, dtype=float)
A = np.column_stack([np.ones(m), t])
true_x = np.array([1.5, 0.30])    # offset (mm), velocity (mm/epoch)
sigma = 0.8
y = A @ true_x + rng.normal(0, sigma, m)
Q = sigma**2 * np.eye(m)

# batch solve using all m observations at once
x_batch = np.linalg.solve(A.T @ np.linalg.solve(Q, A), A.T @ np.linalg.solve(Q, y))

# recursive solve, one epoch at a time: precision, not covariance, accumulates
x_hat = np.zeros(n)
Q_x = np.eye(n) * 1e8   # essentially uninformative prior

for k in range(m):
    Ak = A[k:k+1, :]
    Qk = np.array([[sigma**2]])
    Qx_inv_new = np.linalg.inv(Q_x) + Ak.T @ np.linalg.inv(Qk) @ Ak
    Q_x_new = np.linalg.inv(Qx_inv_new)
    x_hat = Q_x_new @ (np.linalg.inv(Q_x) @ x_hat + Ak.T @ np.linalg.inv(Qk) @ y[k:k+1])
    Q_x = Q_x_new

print("batch:    ", x_batch)
print("recursive:", x_hat)

batch:     [1.32792507 0.30634459]
recursive: [1.32792507 0.30634459]

The two agree to machine precision, exactly as the derivation promised.

What recursive least squares still can’t do

This recursion buys computational efficiency, but it hasn’t touched the conceptual problem at all: $x$ is still, silently, assumed time-invariant across the whole run. A real behavior change partway through will show up as a growing mismatch between predictions and observations, but the update above has no mechanism to let the estimate drift to follow it, every new observation still gets folded into one permanent, ever-more-confident $\hat x$. Making the state itself capable of evolving over time, rather than merely being estimated more efficiently, is the subject of the next post.
